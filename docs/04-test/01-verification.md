# 테스트 명세 — FESTAI

[요구사항](../01-func/01-requirements.md) · [기술 구조](../03-tech/01-architecture.md) · [실행 명령](../../README.md#테스트)

## 검증 전략

CI는 전용 PostgreSQL 백엔드 테스트와 프론트엔드 테스트·lint·빌드를 실행하며([백엔드 테스트](../../README.md#백엔드-테스트) · [프론트엔드 테스트](../../README.md#프론트엔드-테스트)), 음성 모델과 외부 서비스는 수동 점검한다.

- 백엔드: 도메인·집계·AI(무DB) 및 API·SQL(PostgreSQL) 검증.
- 프론트엔드: 규칙·다국어 사전·lint·빌드 검증.
- 스모크: [완료 기준](../01-func/01-requirements.md#완료-기준) E2E 흐름 확인.

## 아키텍처 경계 검증

[test_module_boundaries.py](../../backend/tests/test_module_boundaries.py)가 내부 계층의 인프라 의존, 타 모듈 내부 직접 참조, [허용 의존성](../03-tech/01-architecture.md#모듈-경계와-의존성)·`api.py`(`__all__`) 준수, 별도 프로세스 import 시 인프라 간접 로딩 여부를 검사하고 가짜 포트로 유스케이스를 검증한다(API·SQL·동시성·롤백 테스트 병행 필수).

## 화면 검증

기본 뷰포트(브라우저 UI 제외): 데스크톱 `1920×1080`, 모바일 `360×784` CSS px.

- 본문 넘침·하단 메뉴·긴 라벨·폼과 다크·고대비·큰 글씨·모션 감소 모드의 선택·오류·포커스 구분을 확인한다(기능은 [검증 전략](#검증-전략) 참조).
- 캡처는 로컬 데모 데이터로 개인정보·비밀키 없이 촬영해 README 사용본만 보관하며, 변경 시 커밋·해상도·데이터 조건을 PR에 기록한다.

## UX 흐름 회귀 검증

- `frontend/tests/visitor-flow.test.mjs`: 하위 화면 직접 진입 후 홈·ESG 복귀, 빈 내 예약에서 탐색 이동, 예약 성공 후 내 예약 전환 검증(화면 계약 검사이며 API 예약 성공을 대체하지 않음).
- 예약 탭 키보드 전환, 긴 프로그램명·44px 인원 선택, 오류 재시도, 다국어·큰 글씨 버튼 넘침을 함께 확인한다.
